# Runtime contract: one smoke and one seed-17 pair

Status: prepared for independent static review. Revision02 retains revision01 input bytes and the three as-yet-unclaimed run directories. The immutable card stays `approved:false`; primary records the user's already-given continuous authorization plus this card hash and review receipt in a separate sidecar. It must not claim the user personally saw a later-generated hash.

The only sequence is `RV_SMOKE_R720_S17_attempt1`, then `RV_R0_S17_attempt1`, then `RV_R720_S17_attempt1`. Each is an independent SUMO start with its own previously nonexistent run directory, complete 0–2700 s window, seed 17, Candidate B BUILD02 network. Maximum three consumed starts, zero retry, zero seed-23/netconvert/TraCI/GUI/controller starts. No formal experiment or thesis inference is authorized.

Before each start, the executable verifies card/approval/review/source/network/schema/executor/test/static hashes, exact argv, SUMO_HOME, unclaimed run root, prior technical/data gates and cumulative envelope. An exclusive lock covers validation and execution. Atomic run-directory creation and fsynced reservation precede Popen. Every reserved attempt is permanently consumed even if Popen fails or the launcher crashes; orphan claims cannot restart. The review JSON itself must have status PASS_STATIC_FINAL, stage exact_runtime_package, and this exact card SHA; an old design review, wrong-card review or non-PASS blocks execution. The next run must not start until the prior gate is independently produced and fully PASS; no zero-exit shortcut.

Per run: 180 s monitored elapsed and 1,500,000,000-byte observed directory stop line. Entire scope: 540 s and 4,500,000,000-byte observed stop line. Polling sleeps 50 ms, but scheduling, directory walks and I/O can increase the effective gap. These are operational stop lines, not strict hard quotas; maximum overshoot is unknown. No stderr suppression or output truncation. Timeout/cap/nonzero/start error preserves logs and partial XML, consumes the claim, blocks every next start and never retries. SIGTERM then SIGKILL is used for the child process group; any unconfirmed termination blocks progression. Subsequent closeout must verify no writer remains and rehash exact final files. The manifest intentionally excludes itself and its later receipt, to avoid circular hashes; the independent gate binds both separately. A `final_output_violation.json` always overrides nominal process-complete status and blocks progression.

Output XML validation and physical review occur after the run, with operator monitoring during execution. Primary must watch available stdout/stderr/SUMO logs while the process is active. No unvalidated keyword classifier or TraCI subscription is introduced; it is not claimed that all events will become visible before exit. If the operator clearly observes an actual collision or teleport while the run remains live, immediately write the one-use physical_stop_request.json in that run directory with event_type collision/teleport, observer primary, exact observed_excerpt and its source_path/observed_unix. Do not use a hypothetical mention or emergency-braking warning as an actual event. The wrapper checks this request every polling cycle, terminates the process group, writes partial_evidence_physical, preserves partial XML/logs, consumes the attempt and blocks retries/all next runs. SIGTERM is an emergency alternative and also produces a terminal failure; record the physical cause in a separate evidence receipt. The observer must not defer a clearly seen event to normal completion.

If an actual collision/teleport is first discovered only after normal completion, preserve the completed output and label the gate complete_evidence_but_comparison_unsuitable_physical_event; block all later runs. An engine Error, malformed/incomplete required output or new structural failure fails acceptance. Emergency braking alone is counted and explained, not automatically rejected. Primary's read cadence and buffered-log visibility limit online detection; this protocol does not claim continuous physical-event sensing.

The gate's fixed 12 check IDs are in `gate_contract.json`; all must have status PASS, no missing or duplicate entries. Primary/data specialist must derive the gate from actual archived outputs and bind the exact analysis version and all evidence. The launcher validates the signed-off evidence bindings, not the scientific truth of a hand-written boolean. Gate preparation therefore remains an explicit professional review step. No new user confirmation is needed between these authorized stages; primary proceeds immediately when this evidence gate passes.
