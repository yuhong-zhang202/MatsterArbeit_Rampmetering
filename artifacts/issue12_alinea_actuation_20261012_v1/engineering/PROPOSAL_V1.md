## 2. Native phase implementation — critical early-close detail

Reuse existing observer, WAIT current-following binding, full identity/dynamics checks, actual-crossing helper, FrameCache, resource watchdog, native log capture and immutable snapshots. Implement only a separate small policy/quantizer and phase-aware ledger/adapter/bridge seams. Do not modify production actor or bypass its fixed-G3 validation. Existing adapter hardcodes G3/24, checkpoint1207 and end1272; a new namespace must bind new event expectations rather than falsely reuse these old timing checks unchanged.

Provisional candidate timing is T24, y5, minimum red2 and maximum G17. G17→y5→r2 are native defaults. Green is a deadline, not a fixed17s allocation: after a fully acknowledged green-motion interval reaches the quota, select native phase1 (yellow) once before the next motion; never jump directly to red. Do not set vehicle speed, stop, acceleration, route or lane.

**Early yellow otherwise advances the next green prematurely.** With the simple native program, an early phase1 starts y5 then the default r2; the native successor would resume G before the intended24s boundary. Minimum remedy: after the first actual red ACK in that cycle, verify phase2/r and exact clock/link, then setPhaseDuration(cycle_end−actual_time), read back nextSwitch==cycle_end before any next simulationStep. The setter changes remaining phase duration, not total cycle duration. At the latest normal red ACK, remaining1s completes the total2s red; earlier closure creates longer red. Never call it on a raw yellow getter whose red event is only pending. If readback is uncertain or insufficient remaining time exists, STOP; do not reset the program or restart green. Fresh original admission at each24s boundary remains required.

Bind all setters, actual TLS state/nextSwitch, phase-motion prediction and after-state. Quota count is observed at discrete ACK boundaries; several IDs may cross the same step, so exact N==quota is not enforced. When the green deadline or native transition is already due, do not call a green-termination setter on the wrong phase. Native yellow/red extra crossings are fully counted and safety/overservice diagnosed. Log one-cycle begin/close, green-ended-by-quota/deadline and total red exposure. One initial program definition plus one green-close and one red-remaining adjustment per cycle is enough; no phase-program matrix/framework.

A three-cycle1272 horizon can remain with activation1200/T24, but the mandatory first controlled-red checkpoint must be tied to its real first-red event and subsequent ACK, not hardcoded old1207. This is new diagnostic identity/event metadata only; old1207 cards and evidence remain immutable. If the eventual reviewed design chooses another finite horizon, bind it before launch; never extend an active run to chase a quota.

## 3. Yellow5 is a reference to review, not a safety certificate

Preserve minimum red2. Do not reduce yellow/red to fit900. Proposal y5 rounds up the cited particular multi-car approximately3.6s assessment to an integer-grid reference and leaves extra temporal margin; that specific paper geometry is not a universal bound. It changes the new diagnostic reference, never old cards/results. With y5/r2 and T24 there is still Gmax17, so no nominal reason to cut safety time.

The currently observed queue starts stationary. Actual lane speed22.22m/s is not an absolute vehicle-speed bound because speed factors vary; the unchanged checked global vehicle max55.56m/s also means y5 cannot be labelled adequate for every possible approach. Comfortable decel4.5, actionStep/timestep1, vehicle length5 and actual before-yellow speeds/distances must enter the review. A conventional point-crossing stopping/clearance timing screen, using explicit1s reaction-reference, is Y≈1+v/(2×4.5)+5/v for v>0. At v22.22 this is approximately3.694s; at30 it is4.5s; at55.56 it is7.263s. These are conditional screening illustrations, not current maximum measured speeds or source-native branch proofs. The5/v term concerns the vehicle body at the meter boundary, not clearance of the entire81.98m internal lane. Stationary/low-speed vehicles should be treated as stoppable observations, not by dividing by zero. The reaction reference is not proof of an extra native action delay; do not double-count tau/action/timestep as independent reaction lags.

Before each yellow, record actual approach population, speeds, distance/length, normal decel, phase/time and receiving/leader state. Use the established native current-following and post-motion checks, red-crossing detection and full logs; no additional layered A1 proof. A state outside the reviewed local timing scope or with unknown binding stops the diagnosis. Source-native yellow can stop vehicles that can brake and pass vehicles already committed; yellow time alone does not force remaining vehicles through. ## 6. Last-arrival braking — minimal post-run quantitative completion

Current [adapter255–267](../../../src/candidate_a_native_receiver_wait_20261012/adapter.py#L255) checks before∩after speed differences and after-population acceleration; arrived IDs disappear and lack the final getter. Keep those existing checks. Do not fill their final acceleration with0 or pretend a normal-arrival ID proves no braking. FCD's last visible pre-removal sample and ordinary TraCI subscriptions are not established to capture the removed vehicle's final motion; a subscription framework is unnecessary.

Fresh official1.26 source inspection supports a simpler terminal-speed join: [MSDevice_Tripinfo.cpp261–281](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/devices/MSDevice_Tripinfo.cpp#L261-L281) captures veh.getSpeed at the arrival notification; [MSLane::executeMovements](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/MSLane.cpp) moves the vehicle before testing arrival and notifying removal; [MSVehicle::updateState / executeMove](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/MSVehicle.cpp) updates speed/mean acceleration before that removal. This supports final microscopic step delta=(arrivalSpeed−beforeSpeed)/dt for normal arrivals under unchanged1s Euler model; it is not an interpolated trajectory or proof of the exact random/safety branch.

Minimum new observation: serialize before-only IDs with last before speed/accel/time/route/lane/type and the actual arrived list. At final EOF, pair every expected normal arrival with exactly one completed tripinfo row, matching ID/type, expected terminal lane, no vaporization/teleport, and the correctly bound interval. Actual existing first removal has before59/ACK60 and tripinfo arrival59: **arrival timestamp binds the simulation interval BEGIN**, not ACK end. The recorded arrival position is the desired boundary, potentially clipped despite an overshooting final move; do not infer a fractional dt from that position.

Existing tripinfo prints speeds at2 decimals, which leaves approximately±0.005m/s quantization. A new diagnostic can set native output precision8 (output formatting only, not dynamics), then use conservative speed-rounding intervals and the unchanged−4.5−1e−6 threshold. A wholly passing interval is PASS; a wholly excessive interval is FAIL; a straddling interval, missing/duplicate/unmatched entry, censored/vaporized vehicle or inconsistent clock is UNKNOWN. Never call a rounded point value an exact final acceleration. Specify sufficient precision and verify its actual text before accepting the audit.

This is a **post-run safety/data gate**, not live per-step universal braking protection: output buffering/vehicle removal prevents promising immediate access to the final value. Known normal arrivals with bound before/arrived telemetry are deferred terminal audit observations, not silently exempted. All other identity/phase/log/receiver/collision/teleport/available-acceleration unknowns retain immediate STOP. No next diagnosis may launch while the terminal audit is incomplete or FAIL/UNKNOWN. The scientific review must explicitly accept this limited runtime/post-run responsibility split; otherwise submit an observability NO-GO, not a fake full-coverage result.
