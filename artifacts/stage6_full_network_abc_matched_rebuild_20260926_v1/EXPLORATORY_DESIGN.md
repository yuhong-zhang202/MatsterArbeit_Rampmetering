# Stage 6 matched full-network exploratory reconstruction

**Status:** Prospective design for this reconstruction; review required before any simulation. Supersedes neither the old plan nor any historical disposition. This is an exploratory model-capability test, not a formal protocol or ALINEA evaluation.

## Question and bounded candidate

Can the existing synthetic network show, in one comparable condition, (A) more realized ramp merging with sustained local M deterioration, (B) M protection under moderate metering without serious R/U cost, and (C) a stronger restriction with clearly larger R/U cost? The old `FULLNET3350_A_R900_S17` remains `A_NOT_EVALUABLE`; the old R0/A static comparison remains `NOT_PAIRABLE`.

Use one previously motivated candidate: qMain 3350.4 veh/h (M1396, `[0,1500)`), qRamp 900 veh/h (R240, `[540,1500)`), U150 and X75 (`[0,1500)`), seed17, 2700 s horizon, 1 s step, unchanged `TV_BUILD01` network, detector definitions, vehicle type and Krauß settings. These numbers are project exploratory choices, not literature thresholds or formal parameters. The historical U=X=0 R900 local signal motivates this single full-network test but cannot supply any leg of its result.

## Exogenous binding

Generate all requested vehicles **before any run** from the existing flow schedules, without reading realized vehicle lane, position, speed, departure, travel time or route from an old run. Fix ID, desired departure, route, type, and a prospectively generated per-ID speedFactor vector. The speedFactor target is the documented default passenger truncated normal `normc(1,0.1,0.2,2)`. In sorted ID order, sample with Python `random.Random(170026).gauss(1.0,0.1)`, reject values outside `[0.2,2]`, and serialize accepted values to ten decimal places. This fixes a new realization from the documented default distribution; it is not a claim to reproduce SUMO's old random stream. The generation seed is separate from SUMO seed17. Record code/runtime and hashes. The vector is identical for common M/U/X across R0/A/B/C and for R across A/B/C. Preserve requested `departLane=best`, `departSpeed=max`, M `departPos=100`, U/X/R `departPos=last`, and deterministic chronological XML ordering. R0 contains M/U/X only. A/B/C add exactly the same R vehicles. A uses the existing `60G` open program, B `22G+3y+35r`, C `12G+3y+45r`; do not retime them after outcomes. They are fixed-time release programs, so this test does not establish ALINEA behavior.

Before execution, independently compare per-ID exogenous fields and every non-intervention file/configuration setting. Use versioned run IDs, separate immutable raw directories, hashes, output manifests and one-use execution receipts. Record software versions, run time, resource stops and failures. This design permits at most **one scientific start per arm, four total**, in the order R0→A→B→C. A failed run is retained. A technical retry is permitted only for a demonstrated engineering failure that prevents an evaluable run, after a versioned fix, renewed engineering/data/scientific review and a new exact binding; it cannot change scientific inputs or be used to search outcomes. Before each exact card, bind a 120 s wall-clock and 100,000,000-byte output stop, checked at 100 ms intervals with possible single-poll overshoot; record the final enforcement receipt. No geometry, car-following, lane-changing, detector, classifier or formal-protocol change is in scope.

## Sequential eligibility and interpretation

1. **R0 and A:** Run new matched R0 and A. Before reading post-activation M outcomes, verify M/U/X requested inputs and `[0,540)` actual insertions and trajectories; investigate material differences. Also reconcile planned, inserted, arrived, unfinished and externally waiting vehicles. If this fails or R merge exposure is unrealized, A is `NOT_EVALUABLE`, and the chain stops. Compare open A with R0 on M-only fixed merge-core cells 13–17, both mainline lanes, `[540,1500)`; show all complete 30 s bins, `[0,540)` and `[1500,2700)` context, absolute speeds, simultaneous counts/concentration and route completion/timeLoss. Require an ordered and spatially coherent sustained response beyond one bin or one vehicle. The two-adjacent-30-s-bin screen is an exploratory convention, not a physical breakdown threshold. Report actual R auxiliary/through entries by 1440, 1500 and 2700 s. Keep P/S/L and the 0.85 reference as unchanged diagnostics.
2. **B only if A supports the pressure leg:** Recheck identical exogenous A/B input and pre-activation M/U/X behavior. For the same fixed cells/windows and full M cohort, require consistent M improvement in local speed/population and route time, delay or passage without an offsetting late-tail loss. Account for B ramp queue extent/count/duration and U complete-cohort external wait, network residence and unfinished vehicles separately. The queue must remain within mapped storage without sustained shared-link U obstruction; near-equal U means alone are insufficient. A mixed result is `NOT_IDENTIFIED` and stops the chain.
3. **C only if B supports M protection:** Recheck exogenous binding. Require more R queue/occupation than B and corroborated U cost, with chronology and complete-cohort censoring. Compare C M outcomes with both B and A to test whether protection persists and report additional C benefit, if any. Do not call U cost physical spillback without mapped blockage evidence.

Show all fixed cells and windows, not a selected favorable subset. Distinguish insertion delay from in-network travel time and local disturbance from persistent effect. Source-region feedback after R activates is a possible mediated effect; assess whether it or a downstream/TLS mechanism better explains M differences before making a merge-specific claim. Treat unexplained material input, insertion, geometry, detector or lifecycle anomalies as `NOT_EVALUABLE`. No parameter search, alternate seed/demand or post-outcome controller adjustment is part of this attempt. Single-seed support establishes a possible synthetic mechanism only; prevalence, robustness, a calibrated real-world effect and a sweet spot require a later formal multi-seed protocol.

**Stage 6 closeout rule:** `COMPLETE` only if all three legs are supported in this one comparable full-network chain after independent engineering, data and scientific review, without an obvious material artifact. If this fixed candidate does not identify a leg, Stage 6 remains `PARTIAL`; one negative condition does not establish general incapability. `FAILED` requires separate independent evidence of a structural defect that cannot be repaired within the accepted thesis scope. Do not splice minimal-module results or historical B/C into the new chain.

## Scientific basis versus project judgment

Sargent's simulation V&V framework separates conceptual/data validity, verification and operational validity; it supplies no transferable local-speed cutoff ([Sargent 2013](https://doi.org/10.1057/jos.2012.20)). The original ALINEA work treats ramp admission as a control input and freeway output as a response, but does not certify these fixed-time signal programs or this network ([Papageorgiou et al. 1991](https://onlinepubs.trb.org/Onlinepubs/trr/1991/1320/1320-008.pdf)). The FHWA microsimulation guidance calls for checking data/implementation errors and multiple seed replications when comparing alternatives statistically; its replication guidance is for alternatives analysis, not a universal prerequisite for observing one exploratory realization ([FHWA 2019](https://ops.fhwa.dot.gov/publications/fhwahop18036/chapter6.htm)). SUMO documents stochastic speed factors and insertion sensitivity to departure rules, motivating prospective common demand and actual-insertion checks ([SUMO randomness](https://sumo.dlr.de/docs/Simulation/Randomness.html); [SUMO FAQ](https://sumo.dlr.de/docs/FAQ.html)). The chosen demand, signal timing, cells, windows and qualitative gate are explicit project judgments under D-011. None of these sources gives a directly portable 0.85 reference, 60 s breakdown definition, queue-acceptability threshold or one-seed causal guarantee.
