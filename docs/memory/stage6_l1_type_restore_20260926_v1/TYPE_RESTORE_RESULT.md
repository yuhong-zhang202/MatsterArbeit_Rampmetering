## Cause and repair path

The installed image's `/v3/atomic/update` handler called `queryL1Records({ recordIds: [id] })` and then used `existing[0]`. The SQLite implementation of `queryL1Records` ignores `recordIds`, so the handler read the first L1 row rather than the requested ID. Its upsert then copied that row's `type`, background and version into the requested ID. This explains the observed `episodic`→`persona` change, English background substitution and anomalous version behavior. The pinned [official API documentation](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2ee22397f6091b8cd3ea847bc1edb04d3bec0c94/MemoryCore/v3-api-memorycore-doc.md) has no type setter for `atomic/update`.

For this one repair, a temporary container copied the pinned image's router source and applied a narrowly scoped patch. It resolves the exact ID from the returned rows and accepts only the fixed project identity, target ID, current type `persona`, version 1, corrected content SHA-256 `126ef8b51f4d949a67f0c417e7de5e912631abe0c78a0987c113cc4a2e6aa67f`, original background and requested type `episodic`. The patch is enabled only by the one-use environment mode. It rejects missing, extra and wrong fields, and rejects a second application. No installed image, direct SQLite row, source receipt or historical correction receipt was altered. The original router SHA-256 is `6ed07380b9a1559c2184c05942aadeba4d906cf665cfdf61b794d2fcf878e36c`; the temporary patched router SHA-256 is `ace9b8d1c87aace56ad0be506ddbad6cab0db066477fdfaa04795f195f0366b0`.
