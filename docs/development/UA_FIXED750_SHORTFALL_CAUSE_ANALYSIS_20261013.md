## 3. 排除到什么程度

- **供给不足未见证据：** 末周期storage有21辆队列，不是没有第二辆可放。
- **相位、应用与计数未见缺陷：** 独立核对7周期/41选定ACK的FCD、TLS、双ACK、入口、Euler位移及G4/y4/r2一致。R13真实留在storage，不是漏记已过线车辆；末周期N1触发Gmax截止，没有提前quota转相或少一秒绿。
- **没有车辆速度setter阻挡：** WAIT是观测分类，不命令车辆setSpeed/setAcceleration，也不暂停正常simulationStep。
- **接收准入通过有边界：** 当时front准入PASS、首车进入并继续运动，未见接收头封死；这不能完全排除第二辆的间接跟驰影响。
- **微观分支未唯一识别：** 实际R13@1264 getter记录σ=0.5，其余已用动力学参数有实际日志。有效Krauss默认、具体vsafe/vmax和RNG draw没有直接观测；不能把缺额唯一归因为随机慢化、反应时间或某个私有分支。

因此，可信判断是“本次实际起步/跟驰轨迹没有在固定G4窗口走够”，不是“某个SUMO内部随机分支已被证明有错误”，也不是“所有750场景必定失效”。

## 4. 最小解决路径

**本轮没有已证实的纯技术缺陷可修；不提交无依据的执行器修补，也不重跑相同70秒试验碰运气。** 现有程序已如实发现服务缺额。本轮必要验证是实际轨迹及日志独立对账，不是重复既有单元测试。问题仍未解决到“实际服务已跟上控制指令”；不能因解释了原因就改成服务PASS。

如果下一任务要改善实际服务，应把它明确列为**服务政策/相位预算评议**，而不是bug修复。最小候选方向是给实际两车起步留下更充分的绿灯余量，同时保持周期、黄灯要求和最小红灯之间的可行性。现T10已用满G4+Y4+R2；单独加G1而保留Y4/R2会变T11，名义率2×3600/11≈654.55veh/h，可能让总数更好看却不能称为原750档修复。

可讨论的具体候选为**仅T10条件下Gmax5/Y3/redmin2，提前达两车则仍提前结束G并补足周期红灯**。这是用于检验起步余量是否改善的待审服务方案；多一个G仿真步仅有物理动机，不能由现有0.52m差距推出新轨迹必然过线，也不是安全或放行效果已验证的配置。本次不实现、不运行；Y3能否适用须先审查现有黄灯机制、速度/距离人群及全部保留监测。若提前在G4达quota，候选变为G4/y3/r3，因此连前六周期及后续起始状态都可能改变；旧R13轨迹不能简单外推为新配置第7周期必过。该候选也不能直接覆盖900/T8：按既有库Y≥2/R≥2边界，G5已经需要周期至少9s，统一300–900库仍未解决。若黄灯或全库约束不支持候选，应否决，而不是缩安全余量或改车型。
