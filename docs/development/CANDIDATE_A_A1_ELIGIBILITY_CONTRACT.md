## 3. Concrete native local predicates and domains

For a non-rail vehicle with semi-implicit Euler step Δ, native speed v≥0 and positive braking b, the pinned brakeGap with headway h is:

`k = int(v/(b Δ)); D(v,b,h) = Δ[kv − bΔ k(k+1)/2] + vh`.

**Offline arithmetic domain.** Native source assigns the quotient to `int steps` and later evaluates `steps+1`; the following product begins with double `speedReduction`, so no integer-square multiplication bound is imposed. C++ guarantees signed int width of at least16 and truncation on floating→integer conversion; unrepresentable conversion is undefined ([basic.fundamental table/paragraph4](https://eel.is/c++draft/basic.fundamental#tab:basic.fundamental.width), [conv.fpint paragraph1](https://eel.is/c++draft/conv.fpint#1)). The offline helper therefore safely computes Python truncation first, then requires `0<=steps<=32766`. Quotient32766.999 remains in-domain; truncated32767 is rejected. This guarantees representability in the language minimum domain, without asserting the actual native compiler width; larger finite cases yield ValueError and diagnosticUNKNOWN. Source receipts are [bound here](../../artifacts/candidate_a_a1_contract_20261011_v1/engineering/v3/CPP_INTEGER_DOMAIN_SOURCE_RECEIPT.json). No native C++ build/execution or general floating-point equivalence proof was performed.

This is [MSCFModel.cpp 76–98](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/cfmodels/MSCFModel.cpp#L76-L98). Planning uses **h=0**, not an automatic extra full vΔ delay. For yellow/red non-rail `b_tls=max(min(tlsYellowMinDecel, emergencyDecel),normalDecel)`. Define native planned distance `seen`, class-sensitive lane `stopOffset=q`, desired `jmStoplineGap=j`. Then:

- `canBrakeBeforeLaneEnd = seen ≥ D(v,b_tls,0)`;
- `canBrakeBeforeStopLine = seen − q ≥ D(v,b_tls,0)` (inclusive equality);
- desired offset starts at `max(j,q)`; if lane-end braking is possible, offset is reduced to `min(desired,seen−D)`; it is then floored at source `POSITION_EPS=0.1 m`;
- stopDist begins `max(0,seen−effectiveOffset)`, but native GLOSA/newStopDist/device branches can alter it;
- the normal wait branch additionally requires yellow/red, `!ignoreRed`, `seen≥mustSeeBeforeReversal`, and internal link checks as applicable. Therefore the first inequality alone is **not sufficient to select the full branch or establish ordinary braking**.

Execution yellow tests `dpi.distance > D(v,normalDecel,0) OR (Euler AND v < normalDecel Δ)`. Its strict comparison differs from planning equality. Beyond-stopline and ignore-red states change execution. Native `ignoreRed` includes influencer red-emergency bit and junction-model red/yellow overrides ([MSVehicle.cpp 7504–7542](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/MSVehicle.cpp#L7504-L7542)); speedMode31 by itself does not demonstrate all JM/device state absent.

The pure Euler maximumSafeStopSpeed scalar first subtracts source `NUMERICAL_EPS=.001 m`, then solves the discrete braking/headway relation ([MSCFModel.cpp 849–871](https://github.com/eclipse-sumo/sumo/blob/fa7df22d7f1c4ae245192ecc32410a49f1ffb2a3/src/microsim/cfmodels/MSCFModel.cpp#L849-L871)). Krauss supplies actionStepLength as headway, applies driver perception, an emergency-relaxation wrapper, and maxNextSpeed cap. `tau` supplies follow/headway/secure-gap behavior; `actionStepLength` and last action offset decide whether a fresh action occurs; Δ controls Euler integration. These three one-second settings have different roles, and none proves an extra second of post-red full-speed travel. Numerical epsilons are software safeguards, not newly approved physical clearances. Normal and emergency decel enter different bounds; the actor currently demands ordinary braking, so a native emergency rescue is not admissible A1 success.
