## 问题与条件

原始请求逐秒进入C，实际入口累计为N。需要说明完整300–900 veh/h请求范围内，累计补偿是否在明确条件下消除持续量化偏差，而不能只用恒定750的有限例子代替一般论证。

以下条件全部必要：初始C=N=0；每秒请求属于[300,900]；采用当前完整T8…24候选与最小绝对预测误差选择；周期连续且没有额外空档；每个完整周期实际恰好放行2辆；身份、计数及所有安全/UNKNOWN检查持续通过。实际运行是否能持续满足这些条件是另一个问题。本次动态运行1233秒STOP，已不满足持续执行条件。

源码依据：[`select_packet`](../../src/candidate_a_cumulative_full_catalogue_20261014/policy.py)、同文件`Ledger.begin_step/end_step`。该文件属于125源冻结包，摘要见[固定750实际报告](CUMULATIVE_FULL_CATALOGUE_NATIVE_REPORT_20261014.md)。边界先注册新请求，使用此前ACK累计C/N选包；实际C随后逐秒按当时请求积分，N按独立入口累加。下一边界若上一完整包N≠2就停止补偿。

## 有界递推

完整周期边界的误差记为D_k=C_k−N_k。周期长度T_k秒，实际请求积分I_k辆，则：

`D_(k+1) = D_k + I_k − 2`，且`T_k/12 ≤ I_k ≤ T_k/4`。

选择器按边界当前请求r，最小化`|D_k + r*T/3600 − 2|`，相同分数取较长周期。预测持常不必实际兑现；积分上下界允许请求每秒变化。

- 若D_k≥2，所有预测误差为正且随T增加，因此选择T8；实际增量属于[−4/3,0]。
- 若D_k≤−4，所有预测误差非正且随T增加，因此选择T24；实际增量属于[0,4]。
- 若−4<D_k<2，任意T8…24的实际增量属于[−4/3,4]，所以下一个误差属于(−16/3,6)。

两侧情况也不会越出区间，故从D_0=0归纳得完整边界`−16/3 ≤ D_k ≤ 6`辆。周期内任一已核账ACK，新增C至多6辆、同包累计N介于0和2，因此可使用更宽界`−22/3 ≤ D(t) ≤ 12`辆。

若无限持续满足全部条件，`3600*(C(t)−N(t))/(t−1200)`趋零，单位veh/h。含义是原始请求积分与实际放行的累计平均率之差趋零；不是C−N本身趋零，也不要求变化请求自身存在长期平均极限。

## 不能据此声称的结论

这是宽松的条件界，不能作为有限窗口可接受误差、服务达标阈值或缺车免责标准。安全STOP、供给不足、下游接收受限、完整周期N≠2、未核账时段或新的额外等待都会使当前持续执行前提不成立。1296秒技术终点及两个48秒块不能证明无限持续服务。
