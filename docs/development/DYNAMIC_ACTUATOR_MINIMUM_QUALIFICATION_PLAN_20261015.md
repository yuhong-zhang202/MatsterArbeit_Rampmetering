## 4. 单次动态验证

保留原需求M3600/R900/U360/X180、seed17、dt1、1200启用和1296技术终点；复用请求时钟1200:300、1201:750、1226:900、1237:300。使用新身份，旧失败不覆盖。

每条指令分别记录原始请求时间、请求值、实际首次G应用时间、延迟、所选周期、实际连续G→y→r和转相时刻。累计补偿按欠额选周期，750与900可能选择同一T8；不能虚报每条新请求都使周期长度改变，也不能强制改周期制造“切换”。

当前连续整数周期8…24秒、只在完整边界应用且无额外等待的实现，未被覆盖的新请求应在下一个边界应用，延迟0…23秒；实际首G的ACK比该运动开始时刻晚1秒，两种时间不能混写。若请求在应用前被更新覆盖，须保留其未应用状态，本次四项请求缺少任意一项实际应用则不能说完整验证了四项序列。0…23来自现有周期上界，不是经验拟定的宽容阈值。

核心核账：

- `C(t)=Σ原始请求(t)×1s/3600`，包括等待应用的请求，不用映射率或已应用名义量替代。
- `N(t)`由独立FCD/跨线记录逐车、逐区间核对；完整周期实测2辆的检查沿用当前机制，实际不足不虚补。
- 报告逐请求、逐完整周期和全观测窗口的C、已应用名义量、E、N、C−N；应用延迟、未应用/覆盖旧请求、最后部分周期及车尾截断单列。
- 未观测的相位/窗口指标为null；实测零保留0。完整周期E与全窗口C/N的支持范围不能混用。

最小动态技术通过要求：四条请求均有绑定的实际应用证据且延迟符合上述边界；所选周期/实际信号与独立重算的冻结政策及顺序一致；每个完整周期实测N=2且全窗口N与FCD逐车一致；安全/UNKNOWN门与日志覆盖有效；逐边界及终点的原始C和C−N均明确交付。当前轨迹的条件误差界只用作算术一致性检查，不作为允许缺车的服务容差。正常退出不是通过条件，单一终点差额不要求为0，也不能用宽松理论界掩盖缺车。本次成功最多支持该条受测动态轨迹的有限技术资格，不能声称任意请求历史或长期服务已合格。

若最后一条请求没有实际应用、完整周期N≠2、未解释欠放或安全/证据UNKNOWN，动态不通过，真实ALINEA不启动。正常终点部分周期仅据实际前缀评价，不能作为完整周期或长期资格。

## 5. 条件性短ALINEA

仅在动态技术通过并完成三方后审后，使用**同一冻结执行器**做一次真实E1→原Feedback→原始请求→实际放行诊断。初始900、原30秒更新时钟、需求/seed/1200–1296保持；不调参数制造变化，不把预录指令当反馈。

两次只能有请求来源差异；执行器源码、跟驰合同、相位库及服务计数规则须同一摘要。动态之后若修改这些相关实现，原动态PASS不能自动给新版本闭环放行，需明确受影响范围及必要验证；不能跨实现拼接资格。

除检测器/反馈公式/实际应用外，必须按同一时间范围直接给出原始C、实际N与C−N轨迹、完整/部分周期服务和pending请求。反馈数值变化但周期未变应如实报告；至少一条非初始反馈请求需实际应用。只跑通信链不算完成，短时结果也不证明长期或全300–900服务资格。

## 6. 有界资源与停止

最多拟议两项运行：一次动态、通过后一次ALINEA；各监控300秒、启动60秒、无固定输出字节上限、至少5GB余量、技术终点1296。这是待批准的最多600秒新增监控预算；10/14实际147.815189833秒继续在旧台账保留，不覆盖或伪作未消耗。无授权不建立release、不启动；技术成功后不因其他档位尚未测试追加矩阵。

遇明确实现缺陷只做必要修复及针对性离线验证。相同输入/规则不变时不重复碰撞同一STOP；如必须改变真实安全标准、车辆模型、正式科研设计或增加复杂等待算法，则明确限制与替代方案，停止无效调试。正式协议不修改。
