## 时间与账目定义

- 车辆账目采用 **before-step**：在标签 `t`，计划、入网、到达分别计 `scheduled < t`、`depart < t`、`arrival < t`。网外等待=`计划-入网`，在网=`入网-到达`。因此每类均满足 `计划=网外等待+在网+到达`。该口径只约束 tripinfo 重建账目；FCD/TLS 保留各自原始标签，不声称同一行的所有数据具有相同 step 边界。例如 0 s 行的 trip 账目为在网 0，并不与原始 0 s FCD 已记录车辆构成守恒矛盾。
- E1 保留原始 `[begin,end)` 30 s 区间，单位分别为 veh/h、m/s、%。它没有被移到区间中心或终点。
- TLS 只在原始标签精确匹配时列出，没有平移，也不据此做相位因果判断。
- 停驶沿用技术阈值 `speed <= 0.1 m/s`。样本数不是独立车辆数、队列长度或延误。
- 网外等待车辆没有轨迹坐标，证据包只报告数量。

## Unknown 与解释边界

- 匝道进入合流区的断面流量 **not measured**。一秒 FCD 过断面重建尚未验证遗漏、重复和时间精度；本次没有计算代理量。
- 有效储存容量、需求实现阈值、清空合格阈值、Breakdown/Capacity Drop 定义均为 Unknown。
- 相似的主线平均速度不能证明全系统稳定；持续增长的网外积压直接排除将该高需求轨迹解释为全局稳态。
- low 与 high 同时改变需求和需求时长，不能作因果比较。单 seed 及每秒重复记录不能替代随机重复。
- 2700 s 没有 FCD/TLS 精确标签；该行的停驶字段为空而不是推断为 0，仅保留 tripinfo 推导的 step 前状态，E1 最后区间是 `[2670,2700)`。

## S1 判断与下一步

现有证据足够提出一个有限时域、从空网加载到最终清空的 G1 候选；不足以支持稳态窗口、正式容量指标或科学结论。合流断面流量缺失不阻碍当前“积压何时、在哪里出现以及需求是否按时实现”的问题，但在未来定量分解主线与匝道通过量前应增加一个 observation-only 的明确断面测量并单独验证。
